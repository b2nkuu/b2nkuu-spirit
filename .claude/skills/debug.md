# Debug / RCA

## พื้นฐาน Mindset
**Gaman** — อดทนด้วยความสงบ อย่ารีบ fix ก่อนเข้าใจสาเหตุ
ความสงบภายใต้แรงกดดันนำไปสู่การ diagnose ที่ถูกต้อง
**Kaizen** — bug แต่ละตัวที่เข้าใจอย่างแท้จริงปรับปรุงระบบให้ถาวร

## กระบวนการ
1. **Reproduce ก่อน**: สามารถทำให้ failure เกิดซ้ำได้อย่างสม่ำเสมอและตามสั่งไหม?
   โดยไม่มีการ reproduce ที่เชื่อถือได้ ทุก hypothesis คือการเดา

2. **ระบุ hypothesis**: เขียนออกมาหนึ่งประโยคว่าคิดว่าเกิดอะไรขึ้น
   การเขียนบังคับให้ความคิดชัดเจนขึ้นและเผยให้เห็นช่องโหว่

3. **ตัดออก อย่าสมมุติ**: ตรวจสอบคำอธิบายที่ง่ายที่สุดก่อน
   อ่าน logs ตรวจสอบ inputs จริงๆ ยืนยัน assumptions

4. **Narrow blast radius**: Binary search call chain
   หาขอบเขตที่แน่ชัดว่าพฤติกรรมที่ถูกต้องกลายเป็นไม่ถูกต้องตรงไหน

5. **ถาม "ทำไม?" ห้าครั้ง**: คำตอบแรกแทบไม่เคยคือ root cause
   ติดตาม chain จนถึงสิ่งที่ไม่ควรเป็นไปได้

6. **แก้สาเหตุ ไม่ใช่ symptom**: Patch ควรทำให้ state ที่ผิดเป็น *สิ่งที่เป็นไปไม่ได้*
   ไม่ใช่ซ่อนมัน ถ้าซ่อนไว้ bug จะกลับมาในหน้าตาอื่น

7. **Document สิ่งที่เรียนรู้**: เพิ่ม test, comment อธิบาย constraint, หรือ postmortem —
   เพื่อไม่ให้ใคร (รวมถึงตัวเอง) ต้องประหลาดใจกับสิ่งนี้อีก

## รูปแบบ Output
- **Reproduction**: เงื่อนไข input และ environment ที่แน่ชัดที่ทำให้เกิด failure
- **Root cause**: หนึ่งประโยคชัดเจน — ไม่ใช่ "มันพัง" แต่คือ "X เกิดขึ้นเพราะ Y"
- **Fix**: อะไรเปลี่ยน และทำไมมันแก้สาเหตุ (ไม่ใช่ symptom)
- **การป้องกัน**: Test หรือ guard ที่จะตรวจพบสิ่งนี้ได้ตั้งแต่แรก

# Gaman (我慢)

## หลักการ
Gaman — "อดทนด้วยศักดิ์ศรีและความใจเย็น" — คือการฝึกรับมือกับความยากลำบาก
ด้วยความสงบ ไม่ใช่ความอดทนเชิงรับ แต่คือความยืดหยัดที่มีวินัยและสงบนิ่งต่อหน้า
แรงกดดันที่บอกให้ลัดขั้นตอน

## ในการพัฒนา Software
การ debug และการจัดการ incident ตอบแทนความอดทน Developer ที่รีบ fix โดยไม่เข้าใจสาเหตุ
จะ ship bug เดิมซ้ำอีกครั้ง Gaman คือวินัยในการชะลอตัวเมื่อแรงกดดันบอกให้รีบ

- เข้าใจ root cause ก่อนเสนอ fix
- Patch ที่ซ่อน symptom อันตรายกว่า bug ต้นฉบับ
- เมื่ออยู่ภายใต้แรงกดดัน คำอธิบายแรกแทบไม่เคยถูก
- Bug ซับซ้อนต้องการเวลาเท่าที่ต้องการ — log ทุกอย่าง ตัดตัวเลือกออกทีละอย่างอย่างเป็นระบบ
- ความสงบทางอารมณ์ระหว่าง production incident นำไปสู่การตัดสินใจที่ดีกว่า

## คำถามนำทาง
- เข้าใจว่า *ทำไม* มันถึง fail หรือแค่รู้ว่า *ที่ไหน* มันถึง fail?
- Fix ที่เสนออยู่แก้ root cause หรือแค่ปิดเสียง symptom?
- ตัดคำอธิบายง่ายๆ ออกก่อนสมมุติความซับซ้อนแล้วไหม?
- รีบเพราะแรงกดดันเรื่องเวลา หรือเพราะเข้าใจจริงๆ แล้ว?
- ถ้า fix นี้ fail เราจะอยู่ในสถานะที่ดีขึ้นหรือแย่ลงสำหรับการ diagnose?

## Anti-patterns ที่ควรหลีกเลี่ยง
- เพิ่ม `try/catch` ที่กลืน error โดยไม่ log
- "แก้" test ที่ fail ด้วยการลบหรือ skip มัน
- Deploy hotfix ก่อนเข้าใจ blast radius
- ปิด bug ว่า "reproduce ไม่ได้" โดยไม่สืบสวนอย่างจริงจัง
- ยอมรับ "ทำงานได้ในเครื่องฉัน" เป็นการแก้ปัญหา

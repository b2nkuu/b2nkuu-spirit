# Ikigai (生き甲斐)

## หลักการ
Ikigai — "เหตุผลของการมีอยู่" — คือจุดตัดระหว่างสิ่งที่รัก สิ่งที่ถนัด สิ่งที่โลกต้องการ
และสิ่งที่เลี้ยงชีพได้ คือจุดมุ่งหมายที่จับต้องได้

## ในการพัฒนา Software
ทุกบรรทัดของ code มีเหตุผลในการมีอยู่ Feature ที่ขาดจุดมุ่งหมายชัดเจนสะสมเป็น
tech debt และภาระทางความคิด สร้างด้วยเจตนา

- ถาม "ทำไมสิ่งนี้ต้องมีอยู่?" ก่อนเขียนบรรทัดแรก
- ถ้าตอบ "ใครได้ประโยชน์และอย่างไร?" ไม่ได้ แสดงว่า feature ยังไม่พร้อมสร้าง
- Code ที่สอดคล้องกับจุดมุ่งหมาย test ง่าย document ง่าย และลบออกได้ง่าย
- Code ที่มีคุณค่าที่สุดที่เขียนได้ บางครั้งคือ code ที่ตัดสินใจไม่เขียน

## คำถามนำทาง
- ทำไมถึงสร้างสิ่งนี้?
- สิ่งนี้สำหรับใคร และแก้ปัญหาอะไรให้เขาในวันนี้ (ไม่ใช่สมมุติฐาน)?
- ถ้าลบสิ่งนี้ออก อะไรจะพังสำหรับ user?
- Feature นี้สอดคล้องกับ mission หลักของ product ไหม?
- วัดได้ไหมว่าสำเร็จหรือไม่?

## Anti-patterns ที่ควรหลีกเลี่ยง
- สร้าง feature เพราะมันน่าสนใจทางเทคนิค
- เขียน code "เผื่อไว้" โดยไม่มี use case ที่ชัดเจน
- ออกแบบเพื่อ user สมมุติในอนาคต ก่อนให้บริการ user ปัจจุบัน
- เริ่มจาก "อย่างไร" ก่อนกำหนด "ทำไม"

# Shokunin (職人)

## หลักการ
Shokunin — "ช่างฝีมือ" หรือ "ช่างศิลป์" — คือการอุทิศตนสู่ความเชี่ยวชาญในงานฝีมือ
ช่าง Shokunin ภาคภูมิใจไม่เพียงแค่ผลลัพธ์ แต่คือคุณภาพของทุกขั้นตอนในกระบวนการ
ตัวงานเองคือมาตรฐาน

## ในการพัฒนา Software
Code คืองานฝีมือ ความแตกต่างระหว่าง code ที่ดีและ code ที่ยอดเยี่ยมคือความใส่ใจ —
ใส่ใจในการตั้งชื่อ โครงสร้าง ความชัดเจน และประสบการณ์ของ developer คนต่อไปที่อ่านงานนั้น

- ชื่อ variable ที่ดีคือของขวัญให้ผู้อ่านในอนาคต
- การตัดสินใจด้าน architecture คือการตัดสินใจด้านการออกแบบ — สมควรได้รับความใส่ใจเท่า UI
- ความเชี่ยวชาญมาจากความลึก ไม่ใช่ความกว้าง — รู้จักเครื่องมือและ domain ของตัวเองอย่างลึกซึ้ง
- Review งานตัวเองราวกับว่าช่างเชี่ยวชาญจะตัดสินทุกบรรทัด
- ความเรียบง่ายยากกว่าความซับซ้อน ความเรียบง่ายคือเครื่องหมายของงานฝีมือ

## คำถามนำทาง
- ภูมิใจพอที่จะโชว์ code นี้ให้ developer ระดับ master ดูไหม?
- ชื่อนี้สื่อสาร intent ได้ทันทีโดยไม่ต้องตีความไหม?
- นี่คือโครงสร้างที่เรียบง่ายที่สุดที่แก้ปัญหาได้ถูกต้องไหม?
- เอาทุกอย่างที่ไม่จำเป็นออกหมดแล้วไหม?
- Developer ที่ไม่รู้จัก codebase นี้จะเข้าใจมันได้โดยไม่ต้องมี comment ไหม?

## Anti-patterns ที่ควรหลีกเลี่ยง
- ตั้งชื่อ variable ว่า `data`, `temp`, `thing`, `result`, `x`
- Code ที่ฉลาดเกินไปจนต้องมี comment อธิบายว่ามันทำอะไร
- รับ "มันทำงานได้" เป็นมาตรฐานเดียว
- ข้าม self-review เพราะเป็น author คนเดียว
- ใช้ความซับซ้อนเป็นสัญญาณของความซับซ้อน
